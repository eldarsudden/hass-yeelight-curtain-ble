# Yeelight Curtain BLE для Home Assistant

Первая экспериментальная версия интеграции YLYDD-0053 (16787461).
Работает локально через Bluetooth API HA: адаптер сервера или ESPHome
Bluetooth Proxy с активными GATT-соединениями.

## Установка

### Через HACS

1. Открыть **HACS → ⋮ → Пользовательские репозитории / Custom repositories**.
2. Добавить `https://github.com/eldarsudden/hass-yeelight-curtain-ble`, тип
   **Integration**.
3. Найти **Yeelight Curtain BLE**, скачать и перезапустить HA.
4. В **Настройки → Устройства и службы** добавить **Yeelight Curtain BLE**
   или настроить обнаруженную гирлянду.

Подготовленная версия HACS указывает минимальную версию HA **2026.11.0**;
проверка выполнена на 2026.11.1.
Добавление пользовательского репозитория не требует включения в общий каталог
HACS. [Инструкция HACS](https://www.hacs.xyz/docs/faq/custom_repositories/).

### Вручную из архива

1. Из архива `yeelight_curtain_ble-0.1.0.zip` скопировать папку
   `custom_components/yeelight_curtain_ble` в каталог конфигурации HA.
   В HA OS получится `/config/custom_components/yeelight_curtain_ble/manifest.json`.
   Для Container использовать каталог, смонтированный в `/config`.
2. Перезапустить Home Assistant.
3. Закрыть Yeelight на телефоне и освободить соединение ноутбука.
4. Открыть **Настройки → Устройства и службы**. Если гирлянда обнаружена,
   нажать **Настроить** у **Yeelight Curtain BLE**. Иначе выбрать
   **Добавить интеграцию → Yeelight Curtain BLE** и указать найденную гирлянду.
5. Подтвердить проверку связи. Интеграция прочитает состояние; при настройке
   она не включает свет и не меняет режимы.

YAML для самой интеграции не нужен.
Сбрасывать гирлянду и повторять сопряжение с телефоном не требуется для
проверенного, уже настроенного устройства.

## ESPHome proxy

В HA должны быть настроены интеграции Bluetooth и ESPHome. В конфигурации
существующего proxy нужны активные соединения:

```yaml
esp32_ble_tracker:

bluetooth_proxy:
  active: true
```

Это фрагмент конфигурации, а не полная прошивка ESP32. Потребуется один свободный
слот соединения. Интеграция поддерживает связь открытой, чтобы получать
уведомления и быстро выполнять команды. Не запускайте параллельно клиент
ноутбука и приложение Yeelight.

Указывать IP-адрес proxy в интеграции не нужно: HA выбирает доступный
контроллер по BLE-адресу гирлянды. UUID из сканирования Mac сюда не переносится.

## Управление

- **Светильник**: питание, яркость 1–100%, список 19 обычных эффектов.
- **Музыкальный режим**: включение/выключение обработки звука самой гирляндой
  (**Sound Source → Device**). Поток звука с телефона не реализован.
- **Музыкальный эффект**: Sound Wave, Shine, Spectrum, Converge, Bounce, Breath.
- **Музыкальная палитра**: 40 палитр из записи приложения.

Когда музыка выключена, выбор музыкального эффекта или палитры сохраняет
предпочтение для следующего включения, не включая музыку. Когда музыка включена,
выбранный параметр применяется сразу. Палитра является сохранённым предпочтением:
устройство не возвращает её цвета при чтении состояния. Исходное предпочтение —
Bounce / Father's Day, как в первой записанной команде приложения.

Обычный эффект выключает музыкальный режим. Включение музыкального режима само
по себе не отправляет команду включения питания: при выключенном светильнике
сначала включите свет. Питание, яркость и ID эффектов проверяются чтением после
команды; запрошенное состояние не выдаётся за подтверждённое. Дополнительно
состояние читается каждые 30 секунд и обновляется по уведомлениям.

## GIF-пресеты

Bonfire, Rainbow и Starry sky используют встроенные эффекты. Остальные 16
обычных пресетов требуют загрузки GIF; файлы из предоставленной записи уже
включены в папку `presets` и проверяются по SHA-256. Интеграция ждёт отдельного
подтверждения каждого блока и завершения файла перед активацией эффекта.

Для передачи нужен ATT MTU не меньше **512** и запись без ответа размером
**509 байт**. Если контроллер/proxy сообщает меньший размер, интеграция выдаст
ошибку. Произвольное дробление такого блока не применяется: оно не подтверждено
записью протокола. Совместимость GIF с вашим proxy ещё требуется проверить.
Питание, яркость, встроенные и музыкальные эффекты не требуют передачи GIF.

## Что проверено

- На реальной гирлянде с ноутбука: самостоятельное подключение, чтение состояния,
  выключение с `ok`, уведомлением `power: off` и ответным чтением. Пользователь
  подтвердил фактическое выключение.
- Новый транспорт этой интеграции отдельно проверен чтением реальной гирлянды
  с Bleak 3.0.2; настройки при этом не менялись.
- В изолированной среде HA 2026.11.1 проверяются загрузка компонента,
  настройка, сущности, команды, ошибки и передача GIF на имитаторе периферии.

На рабочем экземпляре HA и через ESPHome proxy интеграция пока не проверена.
Включение, изменение яркости, пресетов и музыки новым клиентом на настоящем
устройстве ещё требуют проверки. Протокол этих команд подтверждён записями
штатного приложения. Совместимость с другими версиями HA отдельно не проверена.

Первичная настройка после заводского сброса, объединение нескольких гирлянд,
обновление прошивки, рисование своих изображений и Pure Color Mode не реализованы.

## Если связь не устанавливается

Проверить, что proxy видит `YLBT_CURT_…`, поддерживает активные соединения и
имеет свободный слот. Закрыть приложение Yeelight и отключить другие BLE-клиенты.
При потере связи сущности становятся недоступными после неудачного обновления;
следующее обновление пытается восстановить соединение. Команды изменения
состояния автоматически повторно не отправляются.

Для подробного журнала добавить к существующей настройке `logger`:

```yaml
logger:
  logs:
    custom_components.yeelight_curtain_ble: debug
    bleak_retry_connector: debug
```
